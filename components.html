Principles

Five rules that keep Ink & Grid consistent across the portal.

PrincipleMeaning
FlatNo drop shadows. Depth comes from ink borders and the cream/white surface split.
Ink on key containers onlyTables, cards, modals, log viewers, stats, and the app shell use --border-width-key (2px). Inner controls use 1px.
One accentOrange for primary action, active nav, running status, live indicators, and focus. Never decorative chrome.
Mono for machine valuesDigests, hostnames, image refs, log timestamps, scopes, YAML, tokens — always ui-monospace.
Dense but breathablePrefer compact padding (8–12px) over large empty regions. Align to the 4px spacing scale.

Color usage

Do

  • Orange fill for the one primary action per view (Deploy, New project, Copy on token-once).
  • Orange border + subtle fill for the active sidebar item.
  • Orange for running, live streaming dot, and focus ring.
  • Red only for failed status and destructive actions.

Don’t

  • Tint large backgrounds orange.
  • Use accent as body text — use --accent-text.
  • Invent a second brand color for charts or icons in MVP.
  • Put white text on #e85d04.

  • Use mono for digests, hostnames, YAML, tokens, scopes.
  • Give key containers 2px ink + 6px radius + overflow: hidden.

Don’t

  • Mix arbitrary radii (e.g. 8px or 12px) outside the tokens.
  • Apply 2px borders to every input — that belongs on key containers.
  • Remove focus outlines without replacing --focus-ring.

App shell

When to use. Every authenticated page: cream top bar + sidebar, white main. Footer chip shows MCP status.

Do

  • Keep sidebar ~220px; one active nav item with accent border + subtle fill.
  • Breadcrumb in the top bar; page title + actions in .page-header.

Don’t

  • Put primary actions in the sidebar.
  • Use orange as a large sidebar background tint.

Buttons

When to use. One primary action per view; secondary for alternatives; ghost for chrome; danger only inside confirmations.

Do

  • Disable with disabled during in-flight deploys.
  • Primary label is ink on orange (AA).

Don’t

  • Two primaries in one header.
  • White text on #e85d04.
  • Danger buttons as the main page CTA.

Inputs

When to use. Forms for project settings, health paths, compose YAML, and toggles. Errors sit under the field.

Do

  • Use .input-mono / .textarea-yaml for machine values.
  • Toggles: role="switch" + aria-checked.
  • Pair .is-error with .field-error text.

Don’t

  • Placeholder-only labels.
  • Red borders without an error message.

Status pills & badges

When to use. Pills for deploy/runtime state; badges for kind (image/compose) and token scopes (read/deploy/admin).

Do

  • Always include the status word — never color alone.
  • Running = accent; failed = red.

Don’t

  • Custom status colors outside the mapping.
  • Using accent pills for non-running success marketing.

Data table

When to use. Project lists, deploy history, audit log. Wrap in .table-wrap (2px key border).

Do

  • Hostnames and digests in .cell-mono.
  • Highlight in-progress rows with .is-highlight.
  • Relative times; absolute in a tooltip on hover.

Don’t

  • Zebra stripes or drop shadows.
  • Truncating status to a colored dot only.

Deploy log & timeline

When to use. Live or historical deploy output; timeline for step progress beside the stream.

Do

  • Mono body, line numbers, .log-ok / .log-err stream colors.
  • Live: .log-live + pulsing dot; aria-live="polite" on the stream.

Don’t

  • Colored backgrounds per line (keep stream colors on text).
  • Hiding timestamps — operators need them.

Alerts, toast, modal

When to use. Inline alerts for page-level outcomes; toasts for brief confirmations; modal for destructive confirms.

Do

  • Danger confirms use .btn-danger and name the resource.
  • Dialog: role="dialog" aria-modal="true", Escape closes, focus trap in product.
  • Toasts: aria-live="polite".

Don’t

  • Auto-deleting a project without a confirm dialog.
  • Stacking many toasts that block the page.

Do

  • Mask secrets; never re-display a token after dismiss.
  • Token-once: accent key border, warning line, mono value, Copy primary.

Don’t

  • Logging the raw token to the audit UI.
  • Showing secret values in plain text by default.

Code, pagination, skeleton, avatar

When to use. Inline/code blocks for commands; pagination for long lists; skeletons while loading; avatar in the user chip.

Do

  • Inline code for paths and short commands; .pre-block for multi-line payloads.
  • Skeletons match content width, not random bars.

Don’t

  • Emoji avatars in product UI.
  • Pagination without a current-page indicator.

Accessibility

Contrast, focus, keyboard, and ARIA expectations for every interactive pattern.

AreaRequirement
ContrastBody and muted meet AA. Accent text uses --accent-text (~5.0:1). On-accent uses ink (~5.4:1). Danger uses white on #b91c1c.
FocusAll interactive elements show --focus-ring via :focus-visible. Never remove outlines without a replacement.
TabsArrow keys move selection; aria-selected / aria-controls; inactive tabs tabindex="-1".
Dialogsrole="dialog" aria-modal="true", labelled title, Escape dismisses, focus moves into the dialog.
Togglesrole="switch" + aria-checked; space/enter toggles.
Toastsaria-live="polite" on the stack.
ColorDon’t rely on color alone — status pills include a label word (running), not only a dot.

UI writing style

Sentence case, short labels, precise errors — no marketing tone.

Do

  • Sentence case: New project, not New Project.
  • Short verbs: Deploy, Rollback, Logs.
  • Relative times in tables (12m ago); absolute on hover tooltip (2026-11-03 17:20 IST).
  • Errors say what failed and what we did: Health check failed. Previous digest restored.
  • Destructive confirms name the resource: Delete project notes?

Don’t

  • Marketing tone or emoji in product UI.
  • Title Case On Every Button.
  • Vague errors (Something went wrong) with no next step.

Adding a new component

Keep the system closed: tokens first, then classes, then this page.

  1. Prefer composing existing tokens and primitives (.card, .btn, .mono).
  2. Add classes to vibeship.css under a clear section comment — no one-off hex literals in templates.
  3. Key containers get 2px ink + --radius-md + overflow: hidden.
  4. Document the component here with realistic Vibeship copy, When to use, and Do / Don’t.
  5. Note misuse modes in DESIGN-SYSTEM.md if they are easy to get wrong.
  6. Keep JS optional and tiny; progressive enhancement only (tabs, toggle, modal, dropdown, copy, SSE log tail).

Stack reminder. Hono + hono/html templates render these class names. Serve or inline vibeship.css — no bundler.

Delete project notes?

Containers and the Caddy route will be removed. The data/ folder is kept unless you opt in below.
